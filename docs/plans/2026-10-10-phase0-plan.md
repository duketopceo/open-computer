# Plan: Phase 0 — three experiments, then commit

Date: 2026-10-10 · Origin: `docs/brainstorms/2026-10-10-verdict-and-requirements.md`
Posture: validation-first — no build code until the three gates pass. Each experiment is cheap, independently runnable, and kills or confirms a core assumption.

## Gate logic

```
E1 (sandbox spike) ──┐
E2 (router bench)  ──┼── all three resolve → Phase 1 build order is decided by results
E3 (protocol spec) ──┘
```

## E1 — CubeSandbox execution-plane spike

**Question:** does CubeSandbox deliver SPACE-equivalent primitives on our hardware?

- Deploy on Hetzner x86 (bare-metal/KVM path). Attempt aarch64 KVM on omarchy-max as a stretch (Asahi KVM exists; PVM is x86-only, irrelevant for bare metal).
- Exercise: create → exec → auto-pause → resume → CubeCoW clone → rollback; CubeEgress empty allowlist = refused outbound; OpenShell policy inside a microVM.
- **Pass criteria:** cold boot <100ms from template; snapshot/clone/rollback byte-identical; egress deny-by-default verified; license third-party exception list reviewed (core is Apache-2.0).
- **Fail path:** nightona (AGPL Daytona fork) or Cloudflare Sandbox as the execution plane; Firecracker DIY as last resort.
- Deliverable: `docs/execution-plane-eval.md` + demo script.

## E2 — Router bench in `orchestral`

**Question:** does any self-managed routing beat hosted baselines on our workloads?

- Candidates: **openrouter/auto** (market baseline, zero effort), **pplx-decider-v1.1-27b via OpenRouter Decisions API** (no GPU needed), **our Jev** (wisp's qwen3-4b on :8091), optional self-host: vLLM-SR Decision/Vela models.
- Dataset: extend wisp-route-fuzz (180 utterances) → task-type classification + model selection fixtures; add real fleet task traces.
- Metric: exact-match rate on golden set + quality-per-dollar via orchestral's Plan→Delegate→Assemble→Validate→Judge→Retry loop. Bills to the `orchestral-eval-v3` key via `orch`.
- **Pass criteria:** a winner by margin that justifies a service. If `openrouter/auto` wins or ties → **do not build a router**; build only the placement policy (R4) and declare routing done.
- Deliverable: `docs/router-bench-results.md` with reproducible config.

## E3 — Sub-agent filesystem protocol spec

**Question:** what is the minimum spec that gives leases, tombstones, and dependency queueing deterministically?

- Start from OACP (Apache-2.0) envelope: inbox/outbox, message types, shared-memory files. Add what it lacks: lease files with expiry/reclaim, tombstone-based completion signaling, consumer-queues-on-producer ordering.
- Define conformance tests up front (from `docs/determinism.md`): spawn→write→collect, lease expiry reclaim, ordering (consumer queues, never fabricates).
- **Pass criteria:** spec complete enough that two different harnesses (Khan + one more) could implement it; test matrix has a deterministic check per rule.
- Deliverable: `docs/fs-protocol-spec.md` + `tests/conformance/` test list (spec only, no impl in Phase 0).

## After the gates — decision tree

| Outcome | Phase 1 shape |
|---|---|
| E1 pass + auto wins E2 | Execution plane on CubeSandbox; no router service — placement policy only. Cheapest path. |
| E1 pass + decider/Jev wins E2 | Thin router service wrapping the winning backend; OpenRouter remains the fleet API. |
| E1 fail | Fall back per E1 fail path; re-plan Phase 2 around the fallback's limits. |
| E3 spec approved | Phase 2 = implement protocol + conformance tests in Khan. |

## Explicit non-goals for Phase 0

- No runtime orchestrator code, no repo restructure, no CI.
- No harness migration evaluation (Khan stays unless it blocks an experiment).
- No connector/integrations work — that's Perplexity's moat, deliberately out of scope.
- License decision (AGPLv3 vs BSL) still required before first code lands — recommend AGPLv3.
